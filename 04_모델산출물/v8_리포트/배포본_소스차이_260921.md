# 배포본 docx ↔ 빌더 소스 차이 (2026-09-21)

**결론.** 이미 나간 docx 3개는 전부 **42열 판**이고, 그것을 만드는 빌더 소스는 **31열 판으로 고쳐 두었다.** 총책임자 결정으로 재빌드를 보류했으므로 둘이 어긋난 상태다. 어긋난 자리를 여기 적어 둔다 — 회의에서 배포본을 띄워 놓고 설명할 때 이 목록이 있어야 한다.

같은 파일을 덮어쓰지 않는다. 재빌드할 때가 오면 **파일명을 새 날짜로 바꾼다.**

**이 규칙은 이제 코드가 막는다.** 빌더 3개 모두 `OUT` 이 이미 있으면 `SystemExit` 으로 멈춘다 — 종전에는 `build_feature_design_docx.py` 에 보호장치가 아예 없었고, 나머지 둘의 `손수정_보관()` 은 **빌드지문이 다를 때만** 사본을 빼므로 지문이 일치하는 정상 배포본은 그냥 사라졌다. `.gitignore` 가 `*.docx` 라 git 으로도 못 되돌린다. 의도적으로 덮어써야 하면 `OVERWRITE=1` 로 돌린다.

## 세 문서에 공통으로 어긋난 것

**1. 열 수와 묶음.** 31열(①8 ②2 ③6 ④12 ⑤2 ⑥1)이 맞다. 배포본은 42열(①11 ②6 ③8 ④13 ⑤2 ⑥2).

**2. 대표 셀 성능.**

| | 배포본(42열) | 소스(31열) |
|---|---|---|
| 눈 pooled / 보정 AUC | 0.7265 / 0.6580 | 0.7114 / 0.6510 |
| 눈 MCC / BA | 0.3422 / 0.6738 | 0.2792 / 0.6430 |
| 피부 pooled / 보정 AUC | 0.7015 / 0.6470 | 0.6999 / 0.6388 |
| 피부 MCC / BA | 0.2797 / 0.6465 | 0.2802 / 0.6463 |

**게이트 판정은 두 판 모두 눈·피부 미달이다.** 배포본을 그대로 설명해도 결론은 틀리지 않는다.

**3. arm 열 수.** `L2단독` 42→31 · `L2+결합` 70→59 · `L2+L1` 94→83 · `L2+L3` 140→129 · `전체_노선혼합` 220→209. 게이트를 넘은 두 arm 의 값은 피부 `전체_노선혼합` 0.7130→0.7120, 피부 `L2+L1` 0.7000→0.7026.

**4. 묶음별 중요도 합.** 배포본은 ③ 가산식 원값이 1위(눈 36.85% > ④ 33.91%)로 적혀 있다. 31열에서는 눈이 ③ 36.83% ≈ ④ 36.80% 으로 붙고 **피부는 ④ 40.72% > ③ 33.88% 로 뒤집힌다.** 감작 CT 6열을 뺀 자리를 ④⑤가 받은 상대량 변화이고 농도 열이 좋아진 것이 아니다 — 소스에는 그 경고 문단을 넣어 두었다. 나란한 대조는 `v8_노선2정리/중요도_묶음이동.csv`.

**5. `native_복원` 대 `nan0`.** 결론(native 채택)은 같다. 배포본의 피부 격차 서술 `+0.0106 · +0.0030` 이 31열에서는 `0.0098 · 0.0026` 이다.

**6. 설계 결함 절.** 배포본은 결함 4건을 **목록으로만** 적고 "`lib_model.py` 와 `input_dataset_v6.xlsx` 는 버전 고정이라 뺄 수 없다", "실효 열 수는 38" 이라고 쓴다. 소스는 3건을 **열 제외로 정리했고** 비용 표(눈 MCC −0.063 등)를 붙였다. 중복 한쪽을 뺐으므로 "실효 38" 이라는 개념 자체가 없어졌다 — 31이 명목이자 실효다.

**7. 역할 미상 열의 중요도.** `f_pct_unknown` 눈 5.2% · 피부 5.0% → **눈 6.8% · 피부 6.8%**.

## 배포본에 남아 있는 사실오류 3건

열 수와 무관한 오류다. 세 빌더 소스에서는 다 고쳤으므로 배포본을 띄워 설명할 때만 구두로 정정한다. **어느 문서에 있는지가 다르므로** 문서별로 적는다.

| 오류 | 맞는 값 | 있는 문서 |
|---|---|---|
| "피부 `전체_노선혼합` 0.7130 이 게이트를 넘은 **유일한** 구성" | 피부 `L2+L1` 0.7000 도 통과해 **두 개**다. 같은 표 한 줄 위에 "피부 통과" 로 찍혀 있다 | 회의자료 · 보고서 |
| "감작 CT 열 **8개**" | **7개**. 감작은 구분 1 만 나오므로 `_s2` 가 없다 | 피처설계근거 |
| "`f_pct_active` + `f_pct_active_presumed` = **15.1%**" | **15.2%**(42열 기준 중요도 CSV 재집계) | 피처설계근거 |

`L2_피처설계근거_260915.docx` 는 "유일한" 오류가 **없다** — 그림 B1 캡션에 "게이트를 넘은 arm 2개(피부 전체_노선혼합 0.7130 · 피부 L2+L1 0.7000)" 로 맞게 적혀 있다. 그 문서에 정정할 것은 아래 두 건뿐이다. 반대로 회의자료·보고서에는 8개/15.1% 오류가 없다.

31열 판에서는 15.2% 가 아예 없어진다 — 두 열 중 한쪽(`f_pct_active`)이 중복쌍 정리로 빠져 합산할 것이 없다.

## 재빌드 전에 먼저 해야 할 것

`figures/figB1`·`figB2`·`figB3` 는 31열 판으로 다시 그렸다(42열 판은 `figB*_42열.png`). 남은 것은 하나다 —

**`figures/fig_a_feature_importance.png` 는 아직 42열이고, 이 그림을 만드는 스크립트가 저장소에 없다.** 회의자료 4장과 보고서 6장이 이 그림을 싣는데 막대의 열 이름·수치가 본문과 어긋난다. 재빌드하려면 생성 스크립트부터 새로 써야 한다. 입력은 `피처중요도_L2단독31.csv`(상위 12열 막대).

## 일부러 고치지 않은 것

- **`build_feature_report_docx.py` 의 작성자 줄** — 실명이 들어 있다. 이미 나간 문서의 작성자 표기를 조용히 바꾸지 않는다. 실명 정책을 정리할 때 세 빌더를 함께 본다.
