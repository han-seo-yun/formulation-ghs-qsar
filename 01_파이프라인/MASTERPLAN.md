### 0.3 핵심 발견 3건

1. **Track B(GHS-CT)는 현재 데이터로 실행 불가.** `input_dataset.xlsx` ingredient 시트의 `ghs_*`/`cat_*` 컬럼은 성분별 값이 아니라 **제형값을 성분 행에 브로드캐스트한 것**(1675 제형 전부에서 성분간 distinct GHS 조합 = 1). CT 가산식은 성분별 분류 × 성분별 농도를 요구하므로 **성분 단위 GHS 수집이 Track B의 유일한 병목**.
2. **특성 시트가 pH 830건(49.6%)을 신규 확보** → docx 표1의 GHS 비가산성 예외(pH≤2 / pH≥11.5) 게이트를 실제로 구현 가능. input_dataset에는 없던 정보.
3. **독성코드가 눈·피부 동시보유 제형을 184 → 306건으로 확대**(H코드 파싱 기준). NTP 실측(`y_epa_*`)은 눈∩피부=0건이었던 구조적 결함을 SDS 경로가 보완.

## Phase 1 — 독성코드 링크 실패행 추가수집 (병렬 에이전트)

### 대상 정의 및 우선순위

추출정보 미기입 599행 + 실패흔적 메모 298행을 모델가치 기준으로 계층화:

| 버킷 | 정의 | 건수 | 처리 |
|---|---|---|---|
| **P1** | 추출정보 없음 **AND** cat_eye_ghs·cat_skin_ghs 둘 다 없음 → 회수 시 **신규 라벨** | **130** (구조보유 79) | **이번 패스 전량** |
| P2 | 추출정보 없음, 라벨 1개만, 구조 보유 → 다중엔드포인트 보완 | 460 | 후속 배치 |
| P3 | 나머지 추출정보 없음 | 9 | 후속 |
| P4 | 추출정보 있으나 메모에 실패흔적(못찾음 72·로그인 12·403 7·404 4) | 298 | 후속(재검증 성격) |

### 실패 원인 분포 (P1 메모)
`못 찾음` 26 · `성분 불일치` 12 · `도구 제약(웹서치 불가/WebFetch만)` 8+2 · `SDS 없음` 7 · `단일물질 SDS` 5 · `403` 3 · `로그인` 3 · `JS렌더링` 1

→ 원인의 상당부분이 **1차 하네스 에이전트가 WebSearch 없이 WebFetch만 썼기 때문**. 이번 패스는 WebSearch+WebFetch 보유 에이전트로 재시도한다.

> **[2026-08-20 정정 — 위 전제는 사실이 아니었다]**
> 이 환경에는 **WebSearch 도구가 프로비저닝되어 있지 않다.** Phase 1 에이전트 13개가 전원
> 독립적으로 동일 보고를 했다. 게다가 일반 검색엔진이 거의 전부 막혀 있다 —
> DuckDuckGo/Google/Qwant/Mojeek 차단 또는 CAPTCHA, Brave 429, 4get.ca bot-check,
> **Bing 은 질의와 무관한 캐시 결과를 정상 형식으로 반환(검증 없이 쓰면 위험)**.
> 따라서 실제 회수는 **구조화 API 직접 호출**로 이뤄졌다:
> PubChem PUG-View, ECHA substance API, EPA CompTox, pomerix.com 농약 등록 JSON,
> TGSC `search.php` POST, seznam.cz, XML 사이트맵 열거(DoMyOwn 12,678 SDS),
> Corteva `jcr:content.*.agrian.json`, r.jina.ai 프록시, `curl | pdftotext -layout`
> (**WebFetch 는 PDF 를 읽지 못한다** — 이 우회로가 필수였다).
> → 1차 실패의 원인은 "WebSearch 를 안 썼기 때문"이 아니라 **애초에 쓸 수 없었기 때문**이며,
> 후속 패스도 검색엔진 의존 설계로는 재현되지 않는다. 위 API 경로를 정본으로 삼을 것.
> 상세: `LIMITATIONS.md` §L7.

### 2단 수집 전략 (Phase 1의 핵심 설계)

- **Tier 1 — 제품 단위**: SDS Section 2/11 (신호어·H코드·눈/피부/감작성 구분·LD50·LC50) + Section 9의 pH. **Section 3 성분표가 `ingredient_names`와 일치할 때만 기록** (하네스의 ingredient-match 게이팅 유지).
- **Tier 2 — 성분 단위 폴백**: 제품 SDS가 원리적으로 없는 행(NTP 발암성시험 혼합물 `AZT; 3TC`, PCB TEF 이성분 혼합물 등)은 **성분별 GHS 분류를 PubChem LCSS / ECHA C&L에서 수집**. 이는 Phase 0.3-①의 Track B 병목을 직접 해소하므로, "실패"로 버리지 않고 다른 축의 데이터로 회수한다.

13 에이전트 × 10 제품 병렬.

## Phase 2 — 4개 시트 검증란(검증여부) 채우기

현재 4시트 모두 0%. 8637행 전량 웹 재조사는 비현실적이므로 **결정론적 규칙검증 + 에이전트 표본검증** 2층 구조.

### 2.1 규칙 기반 자동판정 (전량, 재현가능)

`검증여부` 드롭다운 4값에 매핑:

- **검증완료** — 추출정보가 존재하고 참조값과 모순 없음 + 출처 존재. 시트별 추가 규칙:
  - 성분: CAS 체크디짓 통과, 추출정보의 성분명/CAS가 참조 컬럼과 일치
  - 제형코드: 추출정보가 CIPAC 96코드(`cipac_codes.json`) 정본에 존재
  - 독성코드: H코드 ↔ 구분 정합(H318→Eye1, H319→Eye2A, H320→Eye2B, H314→Skin1, H315→Skin2, H317→Sens1), 신호어-H코드 정합(H314/H318은 Danger)
  - 특성: 값+단위 파싱 성공, 물리적 범위 sanity(pH 0–14, 인화점 등)
- **정보없음** — 출처는 확인했으나 해당 섹션/값이 문서에 없음 (메모가 그렇게 진술 + 추출정보 공란)
- **재검토필요** — 규칙 위반, 참조값과 충돌, 출처 실패흔적(403/404/로그인/못찾음), 성분 불일치
- **미확인** — 손댄 흔적 자체가 없는 행

### 2.2 에이전트 표본검증
`검증완료`로 자동판정된 행에서 층화표본을 추출해 독립 에이전트가 원출처를 다시 열어 대조. 표본 오류율을 산출해 자동판정의 신뢰도를 정량화(전량 검증의 대리지표).

## Phase 3 — 모델 입력셋 구축 (`input_dataset_v2`)

`input_dataset.xlsx` + 2차 수집분 병합. **성분 블록 / 제형 블록 디스크립터 분리** 구조로 산출.

- `formulation` — 제형 단위 wide (기존 189열 + 2차 수집 신규열 + 제형 디스크립터)
- `ingredient` — 제형×성분 long (**성분별 GHS를 브로드캐스트값과 물리적으로 분리**: `ing_ghs_*` 신규 컬럼)
- `descriptors_ingredient` — 성분 단위 RDKit 디스크립터/지문
- `descriptors_formulation` — 제형 단위 집계·상호작용·물리화학 블록
- `MetaData` — 컬럼 사전, 채움률, 출처계층, 한계
- `provenance` — 값별 출처(원본/2차수집/추론) 추적
