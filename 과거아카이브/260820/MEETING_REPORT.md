## 0. 먼저 3분 요약

1. **데이터는 학습을 시작할 수 있는 상태.** 제형 1,675건 중 **1,525건에 타깃(정답) 부여**.
   눈 1,105 · 피부 992 · 감작 595.
2. **가장 큰 진전은 "음성 샘플" 확보.** 이전에는 "자극 있음" 데이터가 다수이고
   "자극 없음" 데이터가 거의 없어서, 모델이 일괄적으로 "위험하다"고 답해도 점수가 높게
   나오는 실질적 판별력이 없는 상태였다. 감작성 양성률은 87.8% → **64.9%** 로 하락.
   문제 설정이 정상화됨.
3. **모델 성능은 아직 낮은 수준.** 순서형(4단계 구분) 예측이 무작위 대비 3~4배 수준. 상용
   수준은 아니나 "신호 존재"는 확인됨. **핵심 가설(Track B)이 유효** — GHS 가산식이
   언제 틀리는지를 상호작용 피처로 예측 가능(정확도 0.62 vs 우연 0.33).
4. **병목은 모델이 아니라 데이터.** 특히 ⓐ pH 결측 68%, ⓑ 감작성 실측값 0건,
   ⓒ 성분 구조(SMILES) 미확보 32%.
5. **수집 방법론이 시트마다 상이.** 독성코드 시트만 자동화 하네스를 사용했고, 성분·제형코드·
   특성 시트는 문서화되지 않은 수작업이었음. **이번 회의의 최우선 안건은 규칙 통일**(§4).

## 1. 지금까지의 데이터 수집 방법 — 시트별로

배정 시트(`dataset_2차배정.xlsx`)는 5개 시트로 구성: 설명 / 성분 / 제형코드 / 독성코드 / 특성.
**네 시트가 각각 다른 방식으로 수집됨.** 아래는 실제 수집 경위.

### 1.1 한 장 요약표

| 시트 | 행수 | 추출정보 채움 | 메모 채움 | 신규링크 |
|---|---|---|---|---|---|
| **독성코드** | 1,675 | 1,076 (64.2%) | 1,334 (79.6%) | 541 (32.3%) |
| 성분 | 5,287  | 2,587 (48.9%) | 2,364 (44.7%) | 509 (9.6%) |
| 제형코드 | 1,675 | 1,324 (79.0%) | 351 (21.0%) | 200 (11.9%) |
| 특성 | 1,675 | 1,519 (90.7%) | 976 (58.3%) | 889 (53.1%) |

### 1.2 독성코드 시트 — 자동화 파이프라인 (모범 사례)

`formulation_harness/_run_tox/` 의 하네스로 실행. 흐름은 다음과 같다.

```
① 1,675행 → 제품명 중복 제거 → 1,076 고유제품
② 8제품 단위 배치로 쪼개 병렬 에이전트가 SDS 검색·판독
③ ★ 성분일치 게이팅 — SDS Section 3(조성)이 시트의 ingredient_names 와
   일치할 때만 값을 기록. 불일치하면 값을 비운다
④ 4값 판정: found / no_code_in_sds / ingredient_mismatch / unresolved
⑤ 시트 기입 (found + 성분일치 + 분류값 존재 → 추출정보. 아니면 공란)
```

**이 설계의 핵심은 "채우는 것"보다 "틀리게 채우지 않는 것"을 우선했다는 점.** 시트에
힌트로 들어 있던 `tox_source_url` 중 상당수가 **다른 물질의 SDS**였음. 이에 따라 "힌트 링크를
신뢰하지 말고 Section 3 로 검증"을 규칙으로 강제함.

판정 결과 (1,076 제품):

| 판정 | 건수 | 뜻 |
|---|---|---|
| `found` | 749 | SDS 찾고 성분도 일치 |
| `unresolved` | 222 | 쓸 만한 SDS 를 못 찾음 |
| `ingredient_mismatch` | 60 | SDS 는 있는데 성분이 다름 → **기록 거부** |
| `no_code_in_sds` | 45 | 성분 일치하는 SDS 인데 Section 11 에 분류가 없음 |

에이전트 자기평가 신뢰도: high 391 / medium 408 / **low 277**.

**읽은 섹션** — 15개 파라미터, 대부분 **Section 11(독성학적 정보)**:

| 출처 | 파라미터 |
|---|---|
| **Section 2** (라벨 요소) | 신호어, H코드, 그림문자 |
| **Section 11** | 경구/경피 LD50, 흡입 LC50, **눈 자극·손상**, **피부 부식·자극**, **호흡기·피부 감작**, 변이원성, 발암성, 생식독성, STOT-SE, STOT-RE, 흡인유해성 |
| **Section 3** | (게이팅 검증용으로만 읽음) |

⚠️ **Section 9(물리화학, pH 포함)는 이 워크플로가 읽지 않음.** 특성 시트 담당 영역이나 해당
시트는 하네스를 사용하지 않았음. 결과적으로 **pH 는 체계적으로 수집된 적이 없음.** 현재
영향이 가장 큰 결측(§5).

### 1.3 성분 시트 — 수작업, 채움률 최저

추출정보 형식은 `성분명 | CAS | 함량`.

```
Xylene | 1330-20-7 | 60-100%
Lamivudine | 134678-17-4 |            ← 함량 칸 비어 있음
```

메모 2,364건의 실제 분포:

| 메모 유형 | 건수 | 비율 |
|---|---|---|
| **SDS 못 찾음 / 자료 없음** | 1,362 | 57.6% |
| **CAS 비움** | 939 | 39.7% |
| **함량 못 찾음 → 함량 칸 비움** | 781 | 33.0% |
| 단일물질 SDS 로 대체 | 169 | 7.1% |
| 문서 안 열림 / 접근 차단 | 139 | 5.9% |
| 시트에 근거 링크 없음(제품명에서 파싱한 행) | 54 | 2.3% |

**SDS 가 없을 때의 실제 처리:**
- 값을 **비움**(추정하지 않음) — 적절한 처리.
- 일부는 **단일물질 SDS 로 대체**(169건). 제품 조성은 미확보, 해당 성분 하나의 정보만 확보.
- 함량 판독 실패 시 성분명·CAS 만 남기고 함량만 비움 → **부분 채움 행 다수**.

**결과적 문제**: 함량이 비면 **GHS 가산식(CT) 산출 불가.** CT 가 산출된 제형이
1,675 중 719건(43%)에 그친 근본 원인. 구조(SMILES) 확보율도 67.6%(3,574/5,287) 수준.

### 1.4 제형코드 시트 — 채움률은 양호

추출정보는 CIPAC 코드 두 글자: `EC`, `SL`, `OD`, `WG`, `SC`…
메모는 21% 에 불과하며, 메모의 **58.7%가 `other`** — "제형이 아님"(원제·단일물질·
연구용 화합물)의 의미로 사용한 것으로 추정.

**SDS 가 없을 때**: 대부분 **제품명·라벨 텍스트에서 코드를 유추**("~ EC", "~ 수화제" 등).
별도 근거를 남기지 않은 경우가 많음(신규소스링크 11.9%).

⚠️ **이 시트는 규칙 기반 확인만 통과했다** (검증완료 1,321 / 재검토 3). 규칙 엔진이
"코드가 CIPAC 96종 목록에 있는가"만 확인할 수 있었기 때문. **코드의 정확성은 확인되지
않은 상태.** 근거 링크가 없어 확인 수단이 없음.

### 1.5 특성 시트 — 채움률 최고, 단 유의점 존재

추출정보 형식은 `값 (항목명)` 파이프 구분.

```
Clear liquid (Appearance) | -48 C (Melting point) | 138 C (Boiling point) |
27 C at closed cup (Flash point) | 0.93 kPa (Vapor pressure) | 0.87 (Relative density) |
Very slightly soluble in cold water (Water solubility) | log Kow 0.05 (Partition coefficient)
```

**★ 가장 중요한 발견 — 이 시트 값의 상당수는 "제품 값"이 아님.**
메모 976건 중:

| 메모 유형 | 건수 | 비율 |
|---|---|---|
| **단일물질 / 원제 / 활성성분 물성** | 621 | **63.6%** |
| **"제품 값 아님" 명시** | 469 | **48.1%** |
| 문서 안 열림 | 15 | 1.5% |

실제 메모: `제품 값 아님 · 활성성분 Beta-nitrostyrene 고유 물성`, `순수물질 물성값`,
`활성성분 원제 문서 기준`

**즉 담당자가 "제품 SDS 가 없어 활성성분 원제의 물성으로 대체"했음을 정확히 기록한 것.
메모 기입은 적절했음.** 다만 이 값을 모델이 제형 물성으로 사용하는 것은 금지.

pH 예시 — 추출정보에 pH 가 언급된 830행 중 **286행에 "제품값 아님" 플래그**가 부착됨.
순수 활성성분의 pH 는 계면활성제·완충제가 포함된 제품 pH 와 상이.
**CT 가산식의 예외 게이트(pH≤2 / pH≥11.5)에 이 값을 사용하면 오분류가 발생한다.**

→ 현재 빌더는 이 구분을 `pc2_*` 계열로 반영했으나, **"제품값 아님" 플래그를 별도
컬럼으로 분리하는 작업은 미완료**(§6 다음주 과제).

**독성코드의 "재검토 필요 1,001건"은 수치가 크지만 부정적 신호는 아님.**
"오류"가 아니라 "제2 출처로 교차확인이 되지 않음"의 의미. 독성 라벨은 모델의 정답이므로
가장 엄격한 기준을 적용함. 성분 시트의 미확인 2,641건은 대부분 **추출정보가 비어 있어
검증 대상 자체가 없는 행**.

각 시트에 `검증근거`·`검증방식` 2열을 추가해, 어떤 규칙으로 해당 판정이 도출됐는지
행마다 확인 가능하도록 함.

**동반된 비용 — 함께 기록:**
- 라벨 충돌(출처 간 불일치)이 눈 69→124 · 피부 67→88 · 감작 1→10 으로 증가.
- 현재 라벨의 13.6%(눈)/13.8%(피부)/**30.9%(감작)** 가 정규식으로 파싱한 자유서술.
- 신규 반영한 LD50 등 수치 피처의 성능 기여는 사실상 0(ablation Δ ≤ 0.04).
  **이번 개선은 "피처"가 아니라 "라벨"에서 발생.**

파싱 시 준수한 5가지 원칙 (팀도 동일 원칙 적용 필요):
1. **결측과 음성을 구분.** "자료 없음" = 결측, "별도 분류 없음" = 음성. 혼용 금지.
2. **정성 서술을 GHS 구분으로 승격하지 않음.** "중등도 자극성"은 구분 2가 아님.
3. **EPA Tox Category(I~IV)를 GHS 로 매핑하지 않음.** 상이한 체계.
4. **엔드포인트 교차오염 금지.** 감작 칸에 기재된 "급성독성 Category 4"를 감작 구분으로 사용 금지.
5. **단위 없는 수치는 폐기.** 밀도·분자량 없이 µL/kg·ppm 을 환산 추정하지 않음.

## 4. ★ 팀에 요청 — 수집 방법론 통일

**이번 회의의 제1 안건.** 현재 시트별 규칙이 달라, 동일한 "빈칸"이 어떤
시트에서는 "없음"이고 어떤 시트에서는 "못 찾음"으로 쓰이고 있음. 모델 입장에서 이 둘은
전혀 다른 정보.

### 4.1 메모 기입 규칙 (전 시트 공통)

하네스 프롬프트에 있던 규칙을 전 시트로 확대 적용해 주세요:

```
메모 = 이상 상황만, 짧게, 한국어로.
· 정상이면 빈칸으로 둔다. "성분정보O, 독성정보O" 같은 완결성 요약은 쓰지 않는다.
· 값을 비웠다면 왜 비웠는지 반드시 적는다.
· 값을 대체했다면 무엇으로 대체했는지 적는다.
```

**태그를 붙여 주세요** — 현재는 자유서술이어서 파싱 오차가 발생함. 앞으로는 맨 앞에 대괄호 태그:

| 태그 | 쓸 때 |
|---|---|
| `[SDS없음]` | 제품 SDS 를 끝까지 못 찾음 |
| `[접근차단]` | 문서는 있는데 403·로그인·CAPTCHA·JS렌더링으로 못 읽음 |
| `[성분불일치]` | SDS 는 열렸는데 Section 3 조성이 시트와 다름 → **값 기록 금지** |
| `[대체:성분SDS]` | 제품 대신 활성성분 원제 SDS 를 씀 |
| `[대체:라벨]` | SDS 대신 EPA 라벨·등록증을 씀 |
| `[제품값아님]` | 적은 값이 제품이 아니라 순수물질·원제의 값 |
| `[구형MSDS]` | GHS 이전 양식(R-phrase 등) |
| `[EPA체계]` | GHS 아닌 EPA 신호어(CAUTION)·Tox Category |
| `[부분]` | 일부 칸만 채움(예: 성분명·CAS 는 있고 함량 없음) |

예: `[대체:성분SDS][제품값아님] 활성성분 Beta-Cyfluthrin 원제 물성. 제품 SDS 미확인`

### 4.2 SDS 가 없을 때의 처리 — **시트별 규칙**

**공통 대원칙: 추정값을 생성하지 않을 것. 비우고, 비운 이유를 메모할 것.**
빈칸은 복구 가능하나, 틀린 값은 모델에 반영되어 성능을 저하시킨다.

#### ① 성분 시트

| 상황 | 이렇게 한다 |
|---|---|
| 제품 SDS 없음 | 1순위: EPA 등록라벨·농약등록증(활성성분+함량 명시됨) → `[대체:라벨]`<br>2순위: 특허·논문의 조성표 → `[대체:문헌]`<br>3순위: **비움** `[SDS없음]` |
| 성분명은 알고 CAS 모름 | **CAS 를 추측하지 말 것.** PubChem/CAS Common Chemistry 에서 이름으로 조회해 확인되면 기입, 아니면 비우고 `[부분]` |
| 함량을 못 읽음 | 성분명·CAS 만 기입, 함량 비움, `[부분]`. **"약 10%" 같은 추정 금지** |
| 함량이 범위(`10-30%`) | **범위 그대로 기입할 것.** 중간값으로 접지 말 것 — 접는 처리는 빌더가 수행 |
| 단일물질 SDS 만 나옴 | 해당 성분 1개 행만 채우고, **나머지 성분 행은 비울 것.** `[대체:성분SDS]` |
| 성분이 "기타 성분 XX%" | `ingredient_name = 기타(비공개)` 로 명시 기입. 비우면 함량 합계 불일치를 감지할 수 없음 |

> **가장 기여도가 큰 항목: 함량.** 함량이 없으면 GHS 가산식 산출이 불가. 현재 CT 산출률이
> 43% 인 원인. **성분명·CAS 보다 함량 회수의 우선순위가 높음.**

#### ② 제형코드 시트

| 상황 | 이렇게 한다 |
|---|---|
| 제품 SDS 없음 | 제품명·라벨의 접미 코드(`~ EC`, `~ 유제`, `~ 수화제`)로 판정 가능 → 기입 + **`신규소스링크`에 근거 URL 필수** + `[대체:라벨]` |
| 근거가 제품명뿐 | 기입하되 메모에 `[추정:제품명]` — 현재 이 구분이 없어 검증이 불가능 |
| 제형이 아님(원제·연구용 화합물) | `추출정보` 비우고 메모에 `[제형아님] 원제` 등 **이유를 기입할 것.** 현재는 `other` 한 단어만 기재되어 의미를 파악할 수 없음 |
| 코드가 CIPAC 96종에 없음 | 임의 생성 금지, 가장 가까운 코드 + 메모에 원문 표기 병기 |

> **요청: 이미 채운 1,324건에 근거 링크를 소급 기입해 주세요.** 현재 신규소스링크가 200건이어서
> 코드의 정확성을 확인할 방법이 없음. 검증 엔진이 "CIPAC 목록에 있는 코드인가"만 확인해
> 1,321건을 통과시켰으므로, 이는 **정확성의 근거가 되지 않음.**

#### ③ 특성(물리화학) 시트

| 상황 | 이렇게 한다 |
|---|---|
| 제품 SDS 없음 | 활성성분 원제 물성으로 대체 **가능**. 단 **반드시** `[대체:성분SDS][제품값아님]` + 어느 성분의 값인지 성분명 명기 |
| **pH** | ★ **최우선 항목.** 제품 SDS Section 9 의 pH 만 유효. 원제 pH 는 `[제품값아님]` 필수. 희석 조건(`1% 수용액 pH 6.5`)이 적혀 있으면 **그 조건도 함께** 적을 것 |
| 성상(고체/액체) | SDS 없이도 제품 사진·판매페이지로 판정 가능. **회수율을 크게 높일 수 있는 항목** |
| 값에 조건이 붙음 | `20000 mg/L at 25 C` 처럼 **조건을 삭제하지 말 것.** 온도 없는 용해도는 활용도가 낮음 |
| 추정값 표기 | `5.2x10-20 mmHg at 25 C estimated` 처럼 원문의 `estimated`/`calculated` 를 **삭제하지 말 것** |

> **pH 회수량이 이 프로젝트의 다음 성능 개선폭을 결정한다.**
> pH 는 단일 피처로도 설명력이 크지만(pH≤2 / ≥11.5 는 기전이 화학적 부식으로 전환),
> **GHS 가산식 적용 가능 여부를 판단하는 게이트**라는 점이 더 중요.
> 현재 533/1,675(32%)만 확보된 상태이며, 그중 286행은 제품값이 아님.

#### ④ 독성코드 시트

| 상황 | 이렇게 한다 |
|---|---|
| 제품 SDS 없음 | **성분 SDS 를 합성해 제품 분류를 생성하지 말 것.** 해당 부분은 모델이 학습할 영역(Track B). 비우고 `[SDS없음]` |
| SDS 는 있는데 성분 불일치 | **값 기록 금지.** `[성분불일치]` — 현재 하네스가 이미 동일하게 처리 중이며 유지 필요 |
| 구형 MSDS(R-phrase) | R-phrase 를 **원문 그대로** 기입. CLP 번역은 코드가 처리(`R41→Eye 1` 등) |
| EPA 라벨(CAUTION 등) | 기입하되 `[EPA체계]`. **GHS 로 환산하지 말 것** |
| Section 11 에 분류 없고 서술만 | **서술문을 원문 그대로 기입.** "중등도 자극성" → 구분 2 로 승격 금지 |
| "분류 대상 아님"/"Not classified" | ★ **반드시 기입 부탁드립니다.** 음성 라벨에 해당하며, 현재 가장 부족한 데이터 |

## 5. 모델 개발 방향 — Track A / Track B

`현 연구의 모델 개발 방향…고찰.docx` 에 정리된 두 갈래를 그대로 구현함.

### 5.1 성분/제형 2층 분리 근거

제형 독성은 「성분들의 성질」 + 「섞여서 생기는 성질」로 구성됨. 한 층으로 통합하면 두 가지
문제가 발생한다.

- **해석력 상실.** 모델이 "logP 가 높아서"라고 설명할 때 *어느 성분의* logP 인지 알 수 없으면
  제형 설계에 활용 불가.
- **GHS 가산식과의 접점 소멸.** 가산식은 정의상 `Σ(성분 구분 × 성분 농도)`.
  성분 단위 표현이 없으면 Track B 구성 자체가 불가능.

```
[성분 블록] 성분 1개 = 1행            [제형 블록] 제형 1개 = 1행
 RDKit 디스크립터 31종               ① 농도가중 모멘트 (가산 성분)
 구조경보 24종 (감작성 핵심)     →   ② 상호작용 항  (비가산 성분) ← 설계의 핵심
 계면활성제 전하 클래스              ③ 제형 실측 물성 (pH·점도·성상)
 지문 (Morgan 2048 / MACCS 167)      ④ GHS-CT baseline (Track B 입력)
```

### 5.2 Track A — 직접 예측

성분·제형 피처를 그대로 입력해 GHS 구분을 예측. 표준적 접근.
학습 가능 행 **1,345**.

### 5.3 Track B — GHS 가산식 잔차 보정 (이 연구의 차별점)

먼저 GHS 규정집의 농도 가산식(CT)을 코드로 그대로 구현. 이후
**"규정식의 오차 크기"** 를 예측한다.

```
타깃 = 실제 구분 − 가산식이 예측한 구분   (resid)
입력 = 상호작용 항 + 예외 게이트 (★ 가산 항은 넣지 않는다)
```

가산 항을 재투입하면 모델이 CT 를 재학습하는 데 표본을 소모함. 학습 가능 행 **652**.

실측 잔차 분포는 다음과 같다:

| 엔드포인트 | n | CT 정확 | CT 과소예측(위험) | CT 과대예측 |
|---|---|---|---|---|
| 눈 | 456 | 190 (42%) | **213 (47%)** | 53 (12%) |
| 피부 | 382 | 260 (68%) | 94 (25%) | 28 (7%) |
| 감작 | 184 | 113 (61%) | 61 (33%) | 10 (5%) |

**GHS 가산식은 체계적으로 위험을 과소평가한다.** 눈에서는 절반 가까이가 실제보다 낮게
산출됨. 이 비대칭은 "상호작용을 반영하지 않은" 데서 발생한 잔차이며, Track B 가 포착하는
신호. **논문의 주장으로 활용 가능한 부분.**

### 5.4 앙상블

CT 커버리지로 라우팅한다. 성분 GHS·함량이 충분히 확보된 행은 Track B 가중을 높이고,
구조는 있으나 성분 GHS 가 없는 행은 Track A 로 라우팅.

### 5.5 현재 성능 (튜닝 전 · 리샘플링 전 · 지문 미포함 = 하한선)

| 과제 | n | F1 | balAcc | 무작위 더미 | 판정 |
|---|---|---|---|---|---|
| 눈 순서형 | 1,105 | 0.499 | 0.496 | 0.128 | ✅ 더미 3.9× |
| 피부 순서형 | 992 | 0.507 | 0.494 | 0.191 | ✅ 더미 2.7× |
| 감작 순서형 | 595 | 0.677 | 0.670 | 0.393 | ✅ |
| 눈 이진 | 1,105 | 0.798 | 0.624 | 0.793 | ✅ 근소 초과 |
| 감작 이진 | 595 | 0.808 | 0.670 | 0.787 | ✅ 근소 초과 |
| **Track B 눈 / 피부** | 456 / 382 | **0.628 / 0.618** | — | ~0.33 | ✅ 우연의 2배 |

**해석 시 유의 — F1 만 보면 반대로 해석하게 됨.**
음성 라벨 추가 전 눈 이진 F1 은 0.832, 현재는 0.798. *하락한 것으로 보임.*
그러나 같은 구간에 더미가 0.838 → 0.793 으로 더 크게 하락했고 balAcc 은 0.593 → 0.624 로
**상승**. 문제 설정이 정상화된 결과이며 모델 성능 저하는 아님.
**보고 시에는 반드시 "더미 대비"와 balAcc 을 함께 제시할 것.**

⚠️ 감작 Track B 는 이전 0.876 → 현재 0.417 이나, **성능 저하가 아니라 클래스 수가
2개→3개로 변경된 데 따른 인공물**(소수 클래스가 10행). n≥30 이 될 때까지 **이 수치는 보고하지 않음.**

### 5.6 누출 차단 (심사에서 확인이 예상되는 부분)

- 라벨을 유도한 원본 컬럼 **228열**을 X 행렬에서 **물리적으로 제외**함. 점검 결과 교집합 0.
- 동일 활성성분을 사용하는 제형이 train/test 로 분리되면 성능이 과대평가됨 →
  **활성성분 CAS 기준 664 그룹**으로 `StratifiedGroupKFold`. 단순 KFold 사용 금지.
- 라벨과 **동일 SDS 문서**에서 도출된 피처 54열은 누출은 아니나 별도 표시함
  (`sds_coderived`). 논문에는 이 열을 제외한 ablation 을 함께 보고.

### 8.3 라벨 충돌 222건 판정

### 8.4 모델링 — 8.1~8.3 과 병행

1. **반복 CV로 전환.** 현재 5-fold 1회여서 순서형 점수가 ±0.03 변동함.
   **5×5 repeated StratifiedGroupKFold** 로 평균±표준편차를 산출. 미적용 시
   "0.499 → 0.512 개선" 같은 의미 없는 보고가 발생.
2. **순서형 프레이밍 정식 구현.** 현재는 다중분류로 수행함.
   누적 이진분류(`P(≥2B)`, `P(≥2A)`, `P(=1)`) 스택으로 전환 — 이진 F1 이 더미를 소폭
   상회하는 상황에서 가장 확실한 개선 수단.
3. **지문 추가.** `fp_form_pooled.npz` 가 생성되어 있으나 아직 스모크에 미반영.
   MACCS(해석 가능) 먼저, Morgan 은 비교군.
4. **불균형 대응**: `class_weight='balanced'` → SMOTE → SMOTEENN 순 비교.
   ⚠️ **리샘플링은 CV 폴드 내부에서만 수행.** 외부에서 수행하면 누출에 해당.
5. **Track B SHAP 분석.** 성능보다 **"어떤 상호작용이 GHS 가산식의 오차를 얼마나 유발하는가"**
   가 이 연구의 실질적 산출물. 계면활성제 전하쌍·용매×logP 항이 실제로 포착되는지 확인.
6. **커버리지 기반 앙상블 라우팅** 구현 (§5.4).

> 산출: `smoke_report_v3.json` + Track B SHAP 그림 + **논문에 넣을 성능표 1장**.

### 8.5 ★ 팀 요청 — pH 1건

단독으로 대체 불가능하고 값이 큰 항목은 **제품 SDS Section 9 의 pH** 하나.

1. **Section 9 만 표적 수집.** 전체 SDS 판독 불필요.
   제형 코드가 `SL`/`SC`/`EC`(액상)인 것부터 — 액상은 pH 가 기재되어 있고 고체는 누락이 잦음.
2. **근거 URL 필수.** 못 찾으면 비우고 메모에 `[SDS없음]` 또는 `[접근차단]`.
3. **희석 조건을 함께 기록**(`1% 수용액 pH 6.5` 등). 원액 pH 와 희석 pH 는 다른 값.
4. 값의 조건(`at 25 C`)과 `estimated` 표기는 삭제 금지.

pH 만 요청하는 근거 세 가지:
- **모델 구조에 직결.** 라벨 품질이 아니라 CT 가산식의 적용 가능 여부를 결정하는 게이트.
  현재 강산 4건·강염기 8건·CT 예외 총 23건만 식별된 상태이고 실제 예외 제형은 더 많을 것으로 추정.
- **로컬 유도 불가.** 제품 단위 실측값이라 구조·성분에서 계산 경로가 없음.
- **분담 효율 최고.** SDS 한 섹션의 숫자 하나여서 화학 지식 없이도 수집 가능.

기존 830행의 `[제품값아님]` 판별은 §8.2 에서 단독 처리하므로, **신규 수집만 요청.**

## 9. 앞으로의 작업 방식 제안

### 9.1 수집 방식을 전부 하네스 방식으로 통일

독성코드 시트만 자동화 하네스를 사용했고, **결과 품질에 뚜렷한 차이가 있었음** — 성분일치
게이팅으로 인해 "틀린 값을 기입하지 않은" 유일한 시트. 나머지 3시트에도 동일 방식을 구축.

핵심은 스크립트가 아니라 **세 가지 규약**.

1. **게이팅**: 문서가 해당 제품의 것인지 확인하는 조건을 시트마다 정의.
   (성분: 조성 일치 / 특성: 제품명 일치 / 제형코드: 등록번호 일치)
2. **4값 판정**: `found` / `못찾음` / `문서있으나불일치` / `해당없음` 을 시트마다 기록.
   현재는 빈칸 하나로 통합되어 구분이 불가능.
3. **근거 링크 필수**: 값을 채운 경우 `신규소스링크`가 있어야 함.
   제형코드 시트가 1,324건을 채우고 링크는 200건인 상황이 반복되지 않도록 할 것.

### 9.2 "채우기 경쟁"을 하지 않음

채움률은 목표가 아님. **틀린 값 1개가 빈칸 10개보다 부정적** — 빈칸은 결측으로 처리되고
`*_isna` 플래그가 부착되나, 틀린 값은 모델에 반영되어 성능을 저하시키고 원인 추적이 불가능.
평가 기준을 "채움률"에서 **"근거링크 동반 채움률"** 로 변경 필요.

### 9.3 원본은 수정하지 않음

현재까지 `dataset_2차배정.xlsx` / `input_dataset.xlsx` 는 수정한 바 없으며,
모든 산출물을 새 파일로 생성함. **이 규칙을 유지.** 재현성과 되돌리기의 근거가 됨.

### 9.4 주간 리듬

```
월~수  단독: §11 2차 판독 → 제품값 플래그 분리 → 라벨 충돌 판정 (재빌드 1회)
월~금  단독: 모델링 병행 — 반복 CV → 누적 이진 스택 → 지문 투입 → Track B SHAP
월~금  팀:   Section 9 pH 수집 (액상 SL/SC/EC 우선, 근거 URL 필수)
금 AM  pH 시트 수령 → 재빌드 + 스모크
금 PM  결과 공유. **성능 변화가 어느 축에서 왔는지** 확인
```

수집과 재빌드의 분리가 중요. 현재는 어떤 값을 채웠을 때 성능이 어떻게 변했는지
추적이 불가능. **축을 하나씩 투입하고 재빌드하면 "감작 라벨 155건 추가로 balAcc 이 얼마 상승",
"pH 150건 추가로 CT 예외 게이트가 몇 건 변경"을 제시할 수 있음.** 이 내용이 논문의
데이터 기여 섹션이 됨.

### 9.5 금지 사항 (합의 요청)

- ❌ 성분 SDS 를 사람이 합성해서 제품 GHS 분류를 생성·기입 
  사전에 계산해 기입하면 Track B 의 타깃이 오염됨.
- ❌ EPA Tox Category(I~IV) ↔ GHS 구분 환산 → 상이한 체계.
- ❌ 정성 서술("중등도 자극성")을 구분 숫자로 승격 → 서술문 그대로 유지.
- ❌ 단위·조건 없는 수치를 환산 추정 → 폐기.
- ❌ 백로그 전량 회수를 목표로 설정 → **일부 제품은 SDS 가 원리적으로 존재하지 않음**
  (단종·규제금지·개발코드·NTP 조제 혼합물). `LIMITATIONS.md` §L7.5.
