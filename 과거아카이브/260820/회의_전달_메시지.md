## A. 팀 채팅방에 붙일 본문

```
지난 회의 내용을 이번 검증 결과까지 반영해서 다시 정리합니다.

■ 1. 팀이 이번 라운드에 한 일 — 확인 완료
성분 시트에서 SDS 재조사로 성분명·CAS·함량을 새로 채운 행 1,432개, 그중 2,105행은
검증여부까지 직접 판정(검증완료/재검토필요/제외)해서 넘겨주셨습니다. 감사합니다.
같은 규칙엔진(work/verify_sheets.py)으로 교차검증했고, 팀이 채운 판정은 덮어쓰지
않고 그대로 유지한 뒤 규칙 판정과 대조만 했습니다. 결과:

  팀 판정 보유          2,105행
  규칙과 일치            1,624행
  규칙과 불일치(재확인 필요)  481행  ← 아래 2번
  "제외" 판정            218행  ← 표준 4값 밖의 신규 값, 처리방침 확정 필요
  팀 미착수             3,182행  ← 규칙판정만 임시로 채워둠

■ 2. 그래서 팀이 다음에 할 일 3가지
(1) 불일치 481건 재확인 — 우선순위는 "추출정보는 비어있는데 검증완료로 표기한 129건"과
    "CAS 체크디짓이 안 맞는 24건". 나머지는 규칙이 과민반응한 경우가 많아 후순위.
(2) "제외" 218건 처리방침 확인 — 완제품 SDS 가 아니라 무관한 시약/표준물질 SDS 가
    섞여 들어간 행들입니다. 학습 데이터에서 완전히 빼는 데 동의하시는지만 확인해주시면
    됩니다.
(3) ★ SDS Section 9 pH 수집 — 지난 회의에서 요청한 그대로 유지. 제품 SDS 의 pH 값
    하나만, 액상(SL/SC/EC) 우선, 근거 URL 필수. 자세한 규칙은 §5.

■ 3. 이번 검증에서 나온 좋은 소식
성분 시트 작업 덕분에, 다음 재빌드에서 웹 접근 없이 이만큼 회복됩니다(파싱 반영 시):
  CAS 확보        2,671 → 3,171행 (+500)
  함량 확보        2,053 → 2,862행 (+809)
  성분 GHS 즉시회수  1,138 → 1,240행 (+102, 이미 확보한 CAS-GHS 대응표와 겹치는 값)
지난 회의에서 "성분 GHS 구분 결측은 웹 접근 없이는 못 푼다"고 말씀드렸는데, 이번 라운드로
그중 일부(102행)는 이미 푼 상태입니다. 나머지는 여전히 웹 접근 필요.

■ 4. 데이터를 "총" 수집하려면 — 지금부터의 절차
지금까지 시트마다 수집 방식이 달랐던 게 가장 큰 비효율이었습니다. 앞으로는 이 순서로
고정합니다.

  1) 수집   : SDS 를 찾아 근거 URL + 값을 채운다 (하네스 방식 — 성분일치 게이팅 필수)
  2) 검증   : 같은 규칙엔진으로 내부정합성 확인 (오늘 한 것과 동일 — CAS 체크디짓,
              참조컬럼 충돌, 메모-값 정합)
  3) 구조화 : 추출정보/자유서술을 모델이 읽을 수 있는 컬럼으로 파싱 (§2.1의 CAS/함량 파싱,
              §11 자유서술 파싱과 같은 성격)
  4) 재빌드 : out/v3/ 생성 → 커버리지·라벨 수 갱신
  5) 재학습 : 어느 축(성분/제형/라벨)이 늘었을 때 성능이 얼마나 움직였는지 확인

이 5단계를 축마다(성분시트 이번 라운드, §11 판독, pH) 반복합니다. 한 번에 다 채우고 한
번에 재학습하면 "무엇이 성능을 바꿨는지" 추적이 안 되므로, 축을 하나 마칠 때마다
재빌드+스모크를 돌려서 기록합니다. 이게 논문의 데이터 기여 섹션이 됩니다.

수집 시 공통 규칙(전 시트 동일 적용):
  · 메모 = 이상 상황만, 짧게. 대괄호 태그 사용: [SDS없음] [접근차단] [성분불일치]
    [대체:성분SDS] [대체:라벨] [제품값아님] [구형MSDS] [EPA체계] [부분] [추정:제품명]
  · 값을 채웠으면 근거 URL(신규소스링크)도 반드시 함께
  · 추정값을 만들어 넣지 않는다 — 모르면 비우고 메모. 틀린 값 1개가 빈칸 10개보다 나쁩니다
    (빈칸은 결측 처리되지만 틀린 값은 원인 추적 없이 성능을 갚아먹습니다)

■ 5. ★ 계속 유지되는 팀 요청 — pH (SDS Section 9)
· 제품 SDS Section 9 의 pH 값 하나만. 액상(SL/SC/EC)부터.
· 근거 URL 필수. 못 찾으면 비우고 [SDS없음] 또는 [접근차단].
· 희석 조건도 함께("1% 수용액 pH 6.5") — 원액 pH 와 다른 값입니다.
· 목표: pH 유효값(제품값) ~247 → 400 이상.
· 왜 이것만: pH ≤2/≥11.5 는 GHS 가산식 적용 여부를 결정하는 스위치이고, 제품 단위
  실측값이라 성분·구조에서 계산할 방법이 없습니다. 이번 성분 시트처럼 SDS 한 섹션만
  보면 되는 작업이라 분담 효율도 가장 높습니다.

■ 6. 모델 학습 방향 — Track A / Track B 다시 설명
왜 두 갈래로 나눠 개발하는지부터 말씀드리면:
GHS 규정은 "제형의 독성 = 성분 독성 × 농도의 단순 합"(가산성)이라고 가정합니다. 그런데
실제로는 성분끼리 서로 영향을 줘서(계면활성제끼리 억제, 흡수 촉진 등) 이 가정이 절반
가까이 어긋난다는 게 문헌으로 확인돼 있습니다. 그래서 이 가정이 언제 맞고 언제 틀리는지를
직접 다루는 모델 구조가 필요합니다 — 그게 두 트랙입니다.

  Track A (직접 예측)
    성분 구조·농도·물성 → 관찰된 GHS 분류를 곧바로 학습. GHS 가산식(CT)은 안 봄.
    데이터가 많아야 성능이 나오는 트랙. 현재 학습 가능 1,345행.
    현재 순서형 성능: 눈 0.499 · 피부 0.507 · 감작 0.677 (더미 대비 1.7~3.9배).

  Track B (CT 잔차 보정)
    "GHS 가산식이 예측한 값" 과 "실제 관찰값"의 차이(잔차)만 학습.
    가산식이 이미 설명하는 부분은 다시 안 배우고, 상호작용(전하쌍·용매×logP 등)만 집중.
    데이터가 적어도 바로 시작 가능 — CT 값은 계산만으로 나오기 때문. 현재 652행.
    현재 성능: 눈 0.628 · 피부 0.618 (3클래스, 우연 0.33) — Track A 순서형보다 높습니다.
    즉 "정확한 구분"보다 "가산식이 어디서 틀리는지"가 더 예측하기 쉬운 문제라는 뜻이고,
    이게 이 연구가 보여줄 핵심 결과입니다.

두 트랙은 최종적으로 앙상블(가중평균)합니다. CT 계산이 가능한 제형(성분 GHS 확보된
719건)은 Track B 비중을 높이고, 구조는 있지만 성분 GHS 가 없는 제형은 Track A 로
처리합니다. 이번 라운드로 성분 GHS 가 늘어나면(§3) Track B 로 넘어가는 표본도 늘어납니다.

성능 볼 때 주의: F1 만 보면 해석이 뒤집힙니다. 음성 라벨이 늘면 F1은 내려가지만 더미도
같이 내려가고 balAcc은 오릅니다. 반드시 "더미 대비 + balAcc" 로 같이 판단해주세요.

■ 7. 다음 주 확인 항목
  성분 시트 불일치 481건        미판정 → 0
  "제외" 218행 처리방침         미확정 → 확정
  성분 GHS 확보                1,138 → 1,240 이상 (이번 라운드분 재빌드 반영)
  감작/눈 라벨 (§11 2차 판독)    595/1,105 → 750/1,200 이상
  라벨 충돌 미판정              222 → 0
  pH 유효값 (제품값)            ~247 → 400 이상   ← 팀 요청
  순서형 성능(반복 CV)          미측정 → 측정완료 + 표 1장

산출물: dataset_배정_검증완료_20260824.xlsx (원본 dataset_배정_검증미완.xlsx 무손상,
검증여부/검증근거/검증방식 3열 포함). 궁금한 행은 검증근거 열에서 왜 그 판정이
나왔는지 바로 확인 가능합니다.

질문/이견은 스레드에 남겨주세요.
```

## B. 짧은 버전 (시간 없을 때 이것만)

```
지난 회의 내용 갱신본입니다.

1) 성분 시트 이번 라운드 작업 검증 완료. 팀 판정 2,105행 중 481건만 규칙과 안 맞아서
   재확인 필요, 218행은 "제외"(무효 데이터) 판정 — 처리방침만 확인해주세요.
2) 좋은 소식: 이번 작업으로 CAS +500행·함량 +809행·성분 GHS 즉시회수 +102행 확보
   (재빌드 시 반영). 웹 접근 없이 나온 결과입니다.
3) 팀 요청은 그대로 pH 1건 — 제품 SDS Section 9, 액상 우선, 근거 URL 필수.
4) 모델은 Track A(직접예측)/Track B(GHS 가산식 오차만 학습) 두 갈래로 진행 중.
   Track B 성능(0.62~0.63)이 Track A 순서형(0.50~0.51)보다 높게 나와서, "가산식이
   언제 틀리는지"를 예측하는 게 이 연구의 핵심 결과가 될 것 같습니다.
5) 앞으로 수집→검증→구조화파싱→재빌드→재학습 5단계를 축 하나씩 반복합니다.
   한꺼번에 다 채우고 한꺼번에 재학습하면 뭐가 성능을 바꿨는지 추적이 안 됩니다.
6) 성능은 F1 단독이 아니라 "더미 대비 + balAcc"로 봐주세요.
```

## C. 참고 — 이번 검증 방법 요약 (질문 대비)

```
Q. 팀이 이미 판정한 검증여부를 왜 다시 검증했나?
A. 덮어쓴 게 아니라 교차검증입니다. 팀 판정은 그대로 최종값으로 남기고, 같은 행에
   규칙엔진(CAS 체크디짓, 참조컬럼 충돌, 메모-추출정보 정합) 판정을 별도로 계산해서
   둘이 다른 경우만 표시했습니다. 규칙과 다르다고 팀 판정이 틀렸다는 뜻은 아니고,
   "한 번 더 보면 좋은 후보"를 자동으로 골라낸 것입니다.

Q. "제외" 판정은 왜 표준 4값(미확인/검증완료/정보없음/재검토필요)에 없었나?
A. 원래 드롭다운 설계 당시 예상 못 한 케이스입니다 — SDS 문서 자체가 해당 제품이
   아니라 무관한 시약 SDS 조합인 경우. 실제로 유용한 판정이라 드롭다운에 5번째 값으로
   추가했습니다.

Q. 이번 라운드 작업이 모델에 바로 들어가나?
A. 아니요. 추출정보는 자유서술 형식("성분명 | CAS | 함량")이라 구조화 컬럼으로 옮기는
   파싱 작업이 한 번 더 필요합니다(§4의 3단계). 그 작업 후 out/v3/ 로 재빌드해야
   실제 학습에 반영됩니다. 현재 제시한 수치(CAS +500 등)는 파싱 시뮬레이션 결과로,
   재빌드 전까지는 잠재치입니다.
```
