# 3노선 비교 배포본 v3 (2026-09-14)

> 1. **성능 게이트를 `roc_auc_보정` 으로 판정한다** (신설 규약 §4.1-3). pooled AUC 는
>    라벨 출처 층 간 유병률 격차(eye 0.19 vs 0.75)를 맞히는 몫을 포함한다. L2 실측에서
>    대표 두 셀이 pooled 로는 게이트 통과였는데 보정하면 둘 다 미달이었다.
> 2. **폴드별 τ 를 그 폴드의 검증분에만 적용한다** (§2.4). 폴드 평균 τ 를 전 행에
>    적용하면 행 i 의 라벨이 나머지 4 폴드의 τ 선택에 참여해 자기 예측에 되먹임된다.
>    L2 실측 편향은 8/8 지표가 낙관 방향이었다.
> 3. **커버리지는 `행커버리지`·`성분커버리지` 두 종류로 구분해 적는다** (§4.2).
>

상대 경로로 배포 기준 동일화. 각자 다른 정보원으로 같은 라벨을 예측하고 결과를 나란히 놓기 위한 공통 자료.

## 쓰는 법

```bash
python3 load_common.py        # 자체검사 + 요약 출력
```

```python
import sys; sys.path.insert(0, "배포_노선분리")   # 압축 푼 위치
import pandas as pd, numpy as np
from load_common import load_folds, select_arm

X_df = pd.read_parquet(".../v4_fixed/X_formulation.parquet")   # 1675행
F = load_folds("eye")
X = select_arm(X_df, "L2단독", F)      # 열은 이름으로 고른다. 마스크도 여기서 적용된다
y = F["y"]

p = np.full((5, len(y)), np.nan)
for si, fi, tr, te in F["folds"]:
    p[si, te] = fit(X[tr], y[tr]).predict_proba(X[te])[:, 1]
```

**열을 위치 인덱스로 고르지 않는다.** 배포본 어디에도 열 이름 → 열 위치 대응표가
없다. `피처노선_arm.json` 은 이름 목록이고, 정본 열 순서는 `sorted(...)` 인데
`X_formulation.parquet` 의 열 순서도 `피처노선_판정.csv` 의 행 순서도 그것과 다르다.
순서를 잘못 짚으면 **조용히 다른 열로 학습**하고 폴드 자체검사로는 잡히지 않는다.
`select_arm()` 은 이름으로 고르고 누락 열을 예외로 던진다.

`load_folds` 는 불릴 때마다 자체검사를 돈다. 두 종류를 구분해서 던진다 — (1) 구조
불변식(25 폴드가 전 행을 1 회씩 덮는지, 모든 폴드에서 검증 그룹 ∩ 학습 그룹 = ∅,
마스크 길이 1675), (2) 버전 정합(n·양성·그룹수를 **같이 배포된 `공통폴드_요약.json`
에서 읽어** npz 와 대조). 기대값을 코드에 박지 않으므로 기준이 바뀌어도 로더를
손으로 고칠 필요가 없고, "손상" 과 "정상 갱신" 이 섞이지 않는다.

## 반드시 지킬 것

- **폴드를 직접 생성하지 않는다.** `StratifiedGroupKFold` 셔플이 달라져 비교가 깨진다.
- **열은 `select_arm()` 으로 이름 기반 선택한다.** 위치 인덱스를 손으로 만들지 않는다.
- **자기 노선 단독 arm 만 대표 산출로 쓴다.** `+결합` arm 과 다른 노선 피처를 섞은
  결과는 부가 행으로만 남긴다. `+결합` 은 성능이 더 나오지만 대표가 될 수 없다 —
  그 열들은 다른 노선의 정보원 없이 계산되지 않아 자기 가설을 반증 불가로 만든다.
- **임계값 0.5 를 쓰지 않는다.** 규약 §2.4 의 중첩 CV + Youden's J 규칙을 따른다.
  **고른 τ 는 그 폴드의 검증행에만 적용한다** — 폴드 평균 τ 를 전 행에 적용하는 것은
  라벨 되먹임이고 실측에서 전 지표가 낙관 방향으로 치우쳤다.
- **결측을 임퓨트하지 않는다.** 규약 §2.6.
- **층별 성능을 반드시 분리 보고한다.** 라벨 출처 층 간 유병률이 4 배 차이나므로
  전체 수치만 보면 라벨 출처 판별을 실력으로 오독한다. 규약 §4.1·§4.1-2.
- **AUC 는 pooled 와 누출보정을 함께 보고한다.** 보정값은 라벨 출처 3 층 내부 AUC 를
  일치쌍수(n_pos × n_neg)로 가중평균한 값이다(규약 §4.1-3). **pooled 단독 인용은 규약
  위반이고, 성능 게이트도 보정값으로 판정한다.**
- **커버리지를 `행커버리지`/`성분커버리지` 로 구분해 적는다** (§4.2). L2 는 규칙
  baseline 을 성분커버리지 구간별로 나눠 함께 낸다 — 집계값 하나로는 답이 되지 않는다.

세부 근거와 금지 사항 전체는 `노선분리_비교규약.md` 를 본다.

**v2 와 달라진 이유.** L2 가 낀 arm 에서 설계 결함 11열을 뺐다 — 죽은 열
`ct_not_applicable` 1, 완전 중복쌍의 한쪽 4(`ct_{eye,skin,sens}_ord`·`f_pct_active`),
감작 CT 6. 근거와 실측 비용은 규약 §5-3 에 있다. **v2 판 수치와 섞어 쓰지 않는다** —
`L2단독` 은 42열판과 31열판이 다른 모델이다. 열 수를 코드에 박지 말고
`피처노선_arm.json` 에서 읽는다.

노선 귀속(L2 = 42열)은 바뀌지 않았다. 빠진 것은 arm 의 대표 자격뿐이고 귀속 기록은
`피처노선_판정.csv` 에 그대로 있다.

`L2L3결합` 28열 = 전하별 계면활성제 농도 6 (전하 클래스가 RDKit SMARTS 유래) +
농도가중 디스크립터 19 (`f_*_wmean`) + 농도×구조량 상호작용 3. 이 노선에는 제외 대상이
없어 `L3+결합`(126)은 변하지 않았다.

대표 관할 `EU_CLP`. 부가 관할(`K_REACH`·`UN_GHS`·`US_OSHA`)의 n·유병률은
`공통폴드_요약.json` 에 함께 담겨 있다. 폴드는 대표 관할 기준으로만 생성했다.

부가 관할을 대조로 돌릴 때: `StratifiedGroupKFold` 는 y 로 층화하므로 **라벨 벡터가
다르면** 배포 폴드를 쓸 수 없다. 행 마스크가 다르기 때문이 아니다 — 실제로 눈은 네
관할 모두 마스크가 동일하고(2B 스위치는 라벨만 바꾼다), 피부 `K_REACH` 는 마스크와
라벨이 대표 관할과 비트 단위로 같아서 **대표 셀과 같은 측정**이 된다. 그런 행을 독립
근거로 세지 않는다.

## 미확정 사항 (결정되면 배포본을 다시 받아야 한다)

- `ph_best` 1 열은 노선 미판정이라 어느 arm 에도 들어가지 않았다 (규약 §5-2).
- ~~`f_ct_sens_*` 7 열~~ → **제외로 확정** (2026-09-21, 규약 §5-3). 죽은 열 1 · 완전
  중복쌍의 한쪽 4 와 함께 11 열을 모든 arm 에서 뺐다. 이 배포본이 그 재발행판이다.
  앞선 판의 "9 열" 은 오기다. 비용은 규약 §5-3 표에 있다 — 눈은 MCC 0.34 → 0.28 로
  유의하게 떨어지고(문서독립 층에서도 남는다) 피부는 보정 AUC −0.0082 를 뺀 나머지가
  잡음 범위다. 게이트 판정은 전후 모두 미달로 바뀌지 않는다.
- `L2L3결합` 28 열의 최종 귀속은 총책임자 확정 대기다 (규약 §5-5). 다르게 정해져도
  `L2+결합`·`L3+결합` 부가 행이 있으므로 재실행 없이 수치를 읽을 수 있다.
